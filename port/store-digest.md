# JDBC storage contract

Scope: Java 21 JDBC only, no Minecraft classes and no runtime configuration lookup. Donor schema reference is exact Bukkit 2.5.5 `storage/DatabaseStorage.java` table definitions at 579-640 plus migrations for the ten member authorization flags, `alias`, `accept_requests`, and the observed MEDIUMTEXT chest column. No live SQL was read or written by this implementation or its tests.

`TeamStore(ConnectionFactory, prefix)` opens one owned connection per call. Prefix must match `[A-Za-z0-9_]+`; donor suffixes and column names use explicit whitelists. Every mutation holds the store monitor, uses prepared values, commits one JDBC transaction, and rolls back on SQL/runtime failure. SQL errors propagate. `validateSchema()` only reads metadata through empty SELECTs for all 22 donor tables, checking required labels, compatible JDBC types, and VARCHAR widths. It does not repair missing donor tables/columns. `provisionAdditiveTables()` is an explicit caller-selected provisioning stage. `createFixtureSchema()` rejects every URL except `jdbc:h2:mem:` and is called only from tests.

`Team`/`Member` expose immutable full row maps, including nullable values, original DOUBLE values, and all ten flags. Mutable JDBC timestamps/byte arrays are copied defensively. Member public reads join the name cache without treating it as membership truth. Authorization flags remain independent of the role.

Writes return boolean except `create` (Team), `mutateBank` (BankResult), journal writes (Operation), and generic update/delete (affected-row int). Main owns caller permissions, fees, tier configuration and external economy orchestration. Upgrade deducts cost and changes the expected tier in one conditional UPDATE. Bank mutations require current membership, optionally require the stored withdraw flag or explicit bypass, and enforce underflow/deposit cap conditions. A matching duplicate opid returns its durable recorded effect even after phase changes, and rejects changed team/player/amount/direction.

`Operation(opid,teamId,player,kind,amount,phase,payload,createdAt,updatedAt)` exposes `effectApplied()`. Payload is a strict JSON object with raw nested values retained. Phase/payload updates merge previous fields and preserve the committed top-level effectApplied flag. Public callers cannot invent TEAM_APPLIED; only the bank mutation writes that phase and marker in the same commit as the bank delta. Bank payload includes bankBalanceBefore/bankBalanceAfter/bankDelta. `beginOperation` retries a known primary-key collision by reading the committed record and checking its identity. Frozen/uncertain journal rows block new money mutations, removal and disband. Pending operations exclude terminal rows and invitation/tag metadata. The journal intentionally has no team FK so financial audit rows survive donor disband; native chests have a cascading FK.

Invites retain donor created_at and keep expiresEpochMillis in a deterministic `invite:<team>:<uuid>` journal sidecar. Existing donor invitations lacking this sidecar cannot be accepted until reissued. Accept checks invitation, expiry, current membership, blacklist and member cap while holding the team row lock. Owner membership cannot be removed or demoted. Tags are checked against donor rows and use unique journal identity reservations; names retain donor uniqueness plus case-insensitive checks. Warp updates preserve ids and use the donor `server_name` column, with the original value untouched until an explicit setWarp call. Team deletion explicitly clears all donor team references (including non-FK historical tables) and preserves money journal records.

`Chest(teamId,formatVersion,inventoryJson,originalSha256,generation,updatedAt)` loads through `chest(int)`. `saveChest(teamId,formatVersion,json,originalSha256,expectedGeneration)` returns false for stale generations; an absent chest is generation 0 and the first save produces generation 1. Original hash cannot change. Donor `team_enderchest.inventory_data` is never updated by native saves. Conversion/codec validation belongs to core.

Generic `insertRow`, `updateRows`, `deleteRows` only permit allies, ally requests, blacklist, custom data, quest progress, homes, rename cooldowns, join requests, player cache and server aliases. They cannot touch team balance/tier/ownership or member permissions. Main handles business rules for these generic rows.

Validation: isolated H2 fixtures cover raw DOUBLE/null/flag preservation, schema/type mismatch, denied withdrawal/bypass/current membership, cap/underflow, durable duplicate opid across terminal phases and two independent stores, journal failure rollback, owner protection, invite expiry/membership/cap/blacklist, upgrade rollback, freeze gating, tag/name uniqueness, warp cap, generic whitelist, create rollback, chest CAS/hash/rollback, and donor cascades with financial audit retention. Runtime MySQL, imported production data and external-economy behavior are unverified here.

Cost mapping source note for core: ConfigManager 801-821 uses feature_costs.enabled=true, economy.enabled=true, items.enabled=false, economy.<feature>=0, items.<feature>, consume_on_use=true. Actual canAffordAndPay slots are team_creation, sethome, home, enderchest, setwarp, warp. Join separately uses economy.team_join and permission_based_join_fee (enabled=true/max_fee=10000) with highest allowed justteams.joinfee.<amount> node. Upgrade charges TeamUpgradeManager.getUpgradeCost(currentTier). No canAffordAndPay call for invite/rename/PVP/bank_deposit/bank_withdraw was found in the exact Bukkit source. These are static source facts, not runtime execution claims.

Final store extensions: `top("members",limit)` returns full donor rows plus member_count from a portable correlated COUNT, ordered count descending then team id. Team-id zero operation queries match only the actor, preventing an actor-only creation/fee freeze from blocking unrelated creators. The six-argument create overload takes color and writes it in the original INSERT transaction; the existing five-argument overload supplies null. Ownership transfer, public join, request approval and invite denial use explicit transactional APIs. Destructive actions deny nonterminal DEPOSIT/WITHDRAW/FEATURE_COST/BANK operations for their team or actor; COMPENSATED is terminal. Transfer retains all raw team fields and extended flags while changing owner UUID, roles and the first four flags atomically. Additional H2 tests cover complete transfer snapshots/rollback, request/public join authorization, cleanup, active operation guards, actor-only freezes, member ranking and atomic create color.
